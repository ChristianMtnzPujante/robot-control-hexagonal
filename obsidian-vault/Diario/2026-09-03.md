# 2026-09-03

Sesión centrada en un único tema: configuración declarativa (YAML) de los
nodos ROS2 del repo, en vez de `declare_parameter`/`create_publisher`
sueltos a mano. Mecanismo completo documentado en [[Anatomía de un Nodo]] —
aquí el orden de los hechos.

- Investigación previa: `ros2 launch` (YAML/XML declarativo oficial),
  `ros2_control`/`ros2_canopen` como precedentes de "manifiesto como dato".
  Conclusión: no existe un "Terraform para ROS2" dedicado — se construye
  encima del launch system, sin inventar un formato nuevo.
- `ros2_kit/node_config.py`: `load_node_config` (YAML → `NodeConfig`, con
  `ParameterDescriptor` real para `range`, tipos de mensaje resueltos vía
  `rosidl_runtime_py`, QoS por nombre) y `apply_node_config` (las llamadas
  `rclpy` reales sobre un `Node` ya construido; callbacks resueltos por
  `getattr`, nunca creados). `Commander` se dejó fuera a propósito
  (subscripciones dinámicas por sesión).
- **Bug real** encontrado construyendo el primer nodo de verdad:
  `rclpy.node.Node` ya usa `self._publishers` como lista interna propia —
  asignar ahí el dict de `apply_node_config` rompía `destroy_node()`.
  Invisible para tests con dobles; solo apareció con `rclpy.init()` real.
  Corregido renombrando a `self._topic_publishers`.
- `docs/configuracion_nodos.md` (nuevo) + `README.md` por paquete.
- Profundización conceptual verificada contra código/documentación real:
  QoS (History/depth, Reliability, Durability, regla "ofrecer ≥ pedir"),
  tipos de mensaje como eje aparte de QoS, y los artefactos reales de
  `rosidl` para `geometry_msgs/msg/Pose` (`cdr_serialize`, `__slots__`,
  setters con `assert isinstance`).
- Publicado el HTML para el tutor "Anatomía de un Nodo" — sustituido el
  07/09 por la nota nativa [[Anatomía de un Nodo]] de este vault.
- `joint_names` configurable desde un URDF: primer intento dentro de
  `robot_node` con corrección posterior vía `set_parameters(...)`;
  cuestionado por el usuario ("¿no debería resolverse antes de construir?")
  → identificado que `urdf_path` es en sí un parámetro overrideable por
  `-p`, solo resoluble una vez el `Node` ya existe. Solución final: la
  derivación se movió a `ControlSession._resolve_joint_names`, antes de
  lanzar el subproceso — ver [[Anatomía de un Nodo]] §5.
- Mecanismo interno de `rclpy` trazado en su código fuente real:
  `Node.__init__` construye `self._parameter_overrides` antes de que
  `apply_node_config` se ejecute.
- Nota abierta: sensación de "caja negra" pese a la explicación con código
  fuente — pendiente un script mínimo que imprima
  `node._parameter_overrides` justo tras `super().__init__()`.
